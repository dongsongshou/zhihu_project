# 知乎同频观点匹配系统

基于 Streamlit 构建的知乎内容主题匹配与讨论关系探索系统，覆盖“内容采集 - 文本清洗 - 特征提取 - 用户画像 - 多信号匹配 - 过程解释 - 群体分析 - 报告输出”的完整链路。系统输出的是公开内容的主题相关性，不等同于真实立场、身份认证或互动成功率。

## 当前入口与版本边界

通过 `home.py` 启动后，主导航仅保留**首页**和**话题探索**。首页使用 `assets/zhihu_cartoon.png`，点击“开始 / 继续话题探索”进入五步流程。

五步页面由 `utils/exploration_ui.py` 渲染，共用 `session_state['exploration']`。顶部、底部都有上一页/下一页按钮和页码；页卡提供轻微翻转、淡入过渡，遵循减少动画的系统偏好。这是步骤式翻页，不是可拖拽的仿真书页。长摘要仍可能需要滚动。

> `pages/` 下的旧页面保留在仓库中，但 `st.navigation` 不再自动将其加入主导航。旧版画像、8 维主题融合、MMR、全局矩阵和群体分析没有全部迁移到新流程。热点内容自动聚类尚未接入；不要将这些能力描述成五步主流程已经完成的功能。

## 功能概览

客户最终获得的是“精选阅读与话题洞察”，而不是一张充满中间变量的算法表。报告优先呈现一句话结论、主要讨论方向、来源覆盖率、Top 5 推荐阅读和原文入口；完整查询、候选摘要和匹配证据放在技术明细中。

主流程围绕同一个话题组织内容，而不是在多个独立候选池之间跳转：

- 话题来源：知乎热榜或自定义话题。
- 多角度检索：保存内容来源、作者展示信息和检索角度。
- 内容审阅：稳定的“对象 N”编号、摘要展开、原文跳转。
- 内容匹配：默认使用 TF-IDF 正文余弦、候选排序和共同特征贡献；第 4 步可选调用知乎直答 `zhida-fast-1p5` 做语义判断，并自动批量排序。
- 作者线索与关系筹备：从高相关内容中提取作者昵称和原文链接，生成“值得进一步了解的作者”候选卡、开场问题、邀请草稿、待联系名单和讨论筹备卡；不自动关注、私信或建群。
- 报告下载：JSON 详细快照与 Markdown 客户摘要报告，包含推荐阅读、作者线索和分析边界。

当前匹配对象是搜索内容，不是已验证身份的用户。

## 推荐演示流程

| 页码 | 页面 | 操作及进入下一页的条件 |
|---|---|---|
| 1 / 6 | 选择话题 | 手动获取热榜或输入主题，点击“确认话题” |
| 2 / 6 | 收集内容 | 选择检索角度，点击检索；至少得到一条有效内容 |
| 3 / 6 | 快速阅读 | 审阅摘要与来源；至少两条内容才能进入匹配 |
| 4 / 6 | 探索关系 | 客户选择一条喜欢阅读的内容，可批量调用大模型语义判断，并生成独立语义排序与综合推荐 |
| 5 / 6 | 发现作者与讨论 | 从相关内容中整理作者昵称、原文入口、开场问题和讨论候选；身份需人工核对 |
| 6 / 6 | 导出报告 | 查看一句话结论、主要方向、优先阅读内容和作者线索，并下载 JSON / Markdown |

检索角度为背景与事实、质疑与风险、实践经验、行业影响、普通人体验。标签代表搜索意图，不代表搜索结果经过立场分类。新流程暂不进行自动内容聚类或角度二次分类。第 5 步会从匹配结果中筛选有昵称和有效知乎原文链接的内容作者线索，但作者昵称不等于唯一身份。

## 会话状态
当前主流程使用统一的 `exploration` 字典：

| 字段 | 用途 |
|---|---|
| `step` | 当前页，内部值 0～4 |
| `anchor` | 已确认话题的标题、链接 |
| `pool` | 本次话题候选内容；与旧版两套候选池独立 |
| `queries`、`errors` | 实际执行批次的查询计划和失败信息 |
| `revision` | 话题变更或重新检索时递增，用于隔离控件状态 |
| `results`、`base` | 当前匹配结果及零起始基准索引 |
| `collected_at`、`method` | 采集时间与匹配方法 |

- 翻页不重复请求接口，已采集内容保留在会话中。
- 确认不同话题时清除旧池和下游结果。
- 点击重新检索时重建候选池，并清空匹配结果。
- 修改检索角度但未点击检索时仍使用旧快照，并显示提示。
- 同一池内展示编号为索引 + 1，排序不改变编号；重新构建池后重新编号。
- 本项目没有持久化会话数据库；浏览器刷新、连接重建或服务重启可能丢失会话，应及时下载报告。

旧版页面使用的字段如下，不会自动同步到新流程：

| 字段 | 作用 |
|---|---|
| `user_candidate_pool` | 候选用户池 |
| `current_profile` | 当前画像结果 |
| `match_result` | 同频匹配结果 |
| `group_analysis_result` | 群体分析结果 |

## 热榜与 API 接入

`zhihu_client.py` 的 `hot_list()` 默认请求 20 条；当前五步流程也请求 20 条，官方范围为 1～30。接口 `/api/v1/content/hot_list` 返回标题、原文链接、缩略图和摘要，不返回热度数值。

`search_zhihu()` 使用 `/api/v1/content/zhihu_search`，每角度请求 1～10 条。鉴权为 Bearer Access Secret 与秒级时间戳，不需要 OAuth。新流程只在刷新热榜或检索按钮触发时调用接口；检索出错后停止剩余角度，保留已取得的部分结果并提示，不自动重试，也不生成模拟结果。

客户端密钥读取顺序：显式参数 → `ZHIHU_ACCESS_SECRET` 环境变量 → 项目根目录 `env` 文件。CLI 密钥链与此 Python 客户端不自动互通。不要提交 `env` 或凭证；历史代码中已有硬编码密钥和调试输出的风险，公开部署前应移除并轮换已暴露凭证。

## 作者候选与关系建立

当前产品链路已经从“推荐相似内容”延伸到“从内容发现值得交流的作者”。第 5 步会为 Top 相关内容生成候选卡，包含作者昵称、内容标题、内容相关分、推荐依据、共同/补充检索角度、建议开场问题和知乎原文链接。客户应先打开原文核对作者和内容归属，再自行决定关注、留言或邀请讨论。

系统支持编辑邀请文案、保存当前会话内的待联系名单、记录手动交流状态和备注、选择多个候选内容生成讨论议程，并导出公开版 HTML 话题卡。分享卡只包含话题、议程和公开来源，不包含私人笔记、联系状态或私人邀请草稿。

以下能力尚未接入：自动关注、自动私信、真实群聊、多用户实时对话、OAuth 身份绑定和持久化社交关系。因此界面使用“内容作者候选/作者线索”，不使用“已匹配用户”或“确定知友”等表述，也不按相同昵称合并身份。

## 客户价值与推荐逻辑

客户只需要选择一个喜欢阅读的对象作为基准内容。系统不会把客户暴露给全部搜索结果，而是按正文 TF-IDF 相似度排序，默认优先推荐 Top 5。每条推荐保留对象编号、标题、相似度、作者和原文入口；共同文本特征用于解释推荐原因。作者推荐是在此基础上增加的关系发现层：只有同时具备正相关内容、非空作者昵称和有效知乎原文链接的结果，才进入作者线索列表。

当前推荐是“相关性优先”的阅读推荐，不是用户推荐，也不是支持/反对立场判定。未来可以在相关性之外加入角度多样性、来源完整度和内容代表性，避免 Top 结果内容过度重复。

## 说明
- 默认流程使用真实搜索摘要做 TF-IDF 词法匹配；开启语义判断后会调用知乎直答 `zhida-fast-1p5`，模型独立判断内容语义相关度、共同兴趣、主要差异和推荐理由。
- 大模型排序使用成功返回的对象；失败请求直接跳过，不使用虚假的中性分数。
- 相同热点检索也可能召回无关内容，当前未实施锚点相关性自动过滤，需要人工核对。
- 搜索返回作者昵称不等于身份验证，也不代表取得其全部创作。
- 作者线索对应的是一条公开内容，不一定对应一个独立用户；同一作者的多条内容可能重复出现，当前不按昵称合并。
- 邀请文案、开场问题和讨论议程是用户可编辑的草案，系统不会代发消息或承诺对方参与。

## 算法执行过程与依据

### 1. 内容采集

当前流程按“热点标题 + 检索角度”调用 `ZhihuClient.search_zhihu()`，过滤无摘要结果，保存标题、摘要、作者昵称和来源。优先以 `(ContentType, ContentID)` 去重；无 ID 时使用完整来源链接，链接为空则使用文本。同一内容多次命中时合并检索角度。

该规则不会去除无 ID 链接中的追踪参数，也不识别不同链接的近似重复文本。接口返回内容只是候选材料，不代表指定用户的全部内容。旧版 `generate_profile()` 仍有关键词兜底路径，但新流程不使用该路径。

### 2. 文本清洗

`clean_content()` 依次进行 HTML 实体解码、标签清除、空白归一化、按行去重，并限制单个对象最多处理 30,000 字符。这样可以降低网页格式和重复摘要对结果的影响，同时不主动删除观点词。

### 3. 特征提取

`content_features()` 对中文提取连续 2、3、4 字片段，对英文提取完整单词。中文通常没有空格，字符 n-gram 不依赖额外分词器；英文统一小写并保留长度大于 1 的单词，但没有翻译或跨语言语义对齐。字符片段可能重叠，因此页面将其称为“共同文本特征”，不把它们直接解释成独立观点证据。

### 4. TF-IDF 建模

对候选池建立统一特征矩阵。TF-IDF 通过降低候选池中普遍出现的词、提高区分度高的词来减少热门词的过度影响；`sublinear_tf=True` 使用对数词频，避免同一词重复出现完全主导结果；`norm="l2"` 便于用向量内积计算余弦相似度。为控制交互成本，最多保留 12,000 个特征。

### 5. 正文相似度

基准文本向量为 x，候选文本向量为 y：

`S_text = (x · y) / (||x|| ||y||)`

页面还计算每个共同特征的贡献：`TFIDF_i(x) × TFIDF_i(y)`。所有共同特征贡献之和等于正文余弦，页面展示贡献最高的 12 项，从而解释“为什么被推荐”。

### 6. 8 维主题向量（旧版模块）

`build_semantic_embedding()` 根据主题词表统计内容命中，形成 8 维主题向量：科技发展乐观、社会公平、文化包容、风险审慎、个人/集体、现实务实、创新接纳、公共参与。向量 L2 归一化后计算主题余弦：

`S_topic = (a · b) / (||a|| ||b||)`

该模块提供稳定、可解释的主题信号，但不是训练型立场识别模型。

### 7. 大模型语义判断（可选）

第 4 步可在 TF-IDF 初筛结果上批量调用知乎直答 `zhida-fast-1p5`。Prompt 要求模型只判断内容核心议题是否相关，不根据作者身份推断，不判断观点正确与否。模型结果包括 `score`、`related`、`common_interest`、`difference` 和 `reason`。

最终排序为：

`S_final = 0.7 × S_llm + 0.3 × S_text`

只有模型请求成功并返回可用结果的对象进入大模型推荐列表；WAF、额度、网络或格式错误的对象跳过。切换“查看得分依据”只读取已缓存的固定排序，不重新调用模型或改变顺序。

### 8. 多信号融合（旧版模块）

**当前五步流程显式使用 `text_weight=1.0`，即只使用正文相似度。候选对象未生成 8 维向量，不展示虚假的主题贡献。** 下述可调融合保留在旧版匹配页面中。


最终匹配分数为：

`S_final = α × S_text + (1 - α) × S_topic`

其中 α 是页面可调的正文权重，默认 0.8。正文承载更具体的语境，主题向量提供更稳定的宏观结构；主题向量不可用时自动退化为正文分数。结果按综合分降序排序，同分按候选索引稳定排序。

### 9. 匹配过程可视化

当前第四页展示固定对象编号下的相似度柱状图、排序表、基准标题、TF-IDF 特征总数以及前 12 个共同特征贡献的明细表。相似度为 0 时可能没有共同特征；所有符合条件的其他内容仍可进入结果列表，目前没有最低分阈值。旧版匹配页另有流程图、融合贡献图和 CSV 导出。

### 10. MMR 多样化推荐（旧版工作台，未迁移）

主题探索工作台采用 MMR，避免推荐对象全部来自同一个主题：

`MMR(i) = λ × S(base,i) - (1-λ) × max(S(i,j))`

第一项鼓励与基准相关，第二项惩罚与已选对象重复。λ 越高越偏同频，越低越偏主题多样性。该方法是可解释的启发式排序，不是成功率预测。

### 11. 作者线索与报告生成

新流程报告面向客户阅读：先展示热点、候选内容数量、来源覆盖率、一句话结论、主要讨论方向、Top 5 优先阅读内容和“值得进一步了解的作者”。作者卡提供内容相关分、推荐原因、建议开场问题及原文入口。技术明细折叠区再提供查询计划、候选摘要、基准对象、匹配证据和算法说明。JSON 是可追溯详细快照，Markdown 是可直接分享的客户摘要，两者都明确展示分析边界，不生成未经证据支持的自动观点结论。

旧版群体报告另对主题维度求均值，该统计不在当前五步流程中。

## 大模型请求与限制

语义判断不是本地模型，而是通过知乎直答接口完成，因此需要有效的 Access Secret、直答权限和可用额度。每个候选对象通常产生一次模型请求，候选数量较多时可能触发 WAF 或频率限制。建议先使用 TF-IDF 筛选，再开启语义判断；接口不可用时关闭开关使用词法匹配。

语义判断返回自然语言或非标准 JSON 时会尝试兼容解析；无法得到可靠结果的对象会被跳过。大模型结果不代表用户真实立场、身份、兴趣一致性或互动意愿。

## 数据结构

当前候选条目字段为 `input_text`、`search_content`、`source_url`、`author_name`、`is_real_search`、`angles`，没有 `embedding`。旧版画像包含 `embedding`、`viewpoint_scores`、`viewpoint_names` 等字段；不要假设旧版 `generate_profile()` 已保留 `raw_items`。内容匹配结果额外包含 `text_similarity`、`topic_similarity`、`text_weight`、`shared_features` 和 `evidence`，保证结果可追溯。

## 评估与后续升级

当前尚未使用人工标注数据集校准参数，建议后续用 Precision@K、Recall@K、NDCG@K 和人工“适合讨论”评分评估。升级路线包括：授权范围内的用户内容接口、句向量与 TF-IDF 双通道、支持/反对/中立方向识别、人工标注排序模型、来源审计和隐私保护。
